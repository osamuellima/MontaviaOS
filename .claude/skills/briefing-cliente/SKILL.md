# /briefing-cliente

Transforma texto solto e desorganizado em briefing com campo separado e leitura rápida do
que importa.

## O que ler antes

- `_memoria/empresa.md` — o que a empresa entrega, pra saber o que perguntar
- `_memoria/preferencias.md` — tom do resumo

## Entrada esperada

Conversa colada, anotação solta ou campos já preenchidos manualmente. Se vier muito
incompleto, sinalizar no fim quais campos essenciais ainda faltam — sem travar a entrega.

## Passos

**1. Extrair e categorizar** tudo que aparece no material bruto: dado do cliente, contexto do
negócio dele, escopo do projeto, referência visual/técnica, condição comercial.

**2. Montar o briefing com campo separado:**

```
BRIEFING — [nome do cliente/empresa]
Data: [hoje]

DADOS DO CLIENTE
Nome / Empresa / Contato / Cidade

SOBRE O NEGÓCIO DELE
Segmento / Serviço principal / Público / Diferencial percebido

SOBRE O PROJETO
Objetivo / Resultado esperado / Prazo / Orçamento mencionado

IDENTIDADE E REFERÊNCIA
Logo (tem / não tem) / Cores / Fontes / Referência visual / Material disponível

PONTOS DE ATENÇÃO
[campo livre]

STATUS COMERCIAL
Primeiro contato / Em negociação / Proposta enviada / Fechado
```

Preencher com o que veio; marcar ausência com travessão, não inventar.

**3. Resumo estratégico** — parágrafo curto (3-5 linhas): quem é o cliente e o que faz, qual o
objetivo central do projeto, e um ponto de atenção ou oportunidade específica — não genérico.

**4. Se faltar dado crítico**, listar objetivamente o que precisa ser confirmado antes de
seguir com o projeto.

## Regras

- Nunca inventar informação — ausência vira travessão ou entra em "falta confirmar"
- Resumo estratégico precisa dizer algo específico daquele cliente, não frase de prateleira
- Conversa longa: extrair só o relevante pro projeto, não transcrever tudo
- Tom de organização, não de venda — briefing não é proposta
